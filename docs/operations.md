# Operations and recovery

The owner console approves/revokes clients and agents, shows last-use and redacted audit records, and controls production brokerage authorization. Enrollment, changes and brokerage controls require owner subject pinning, Google login, recent (five-minute) application MFA and CSRF validation. Revisit Google login/MFA when recent verification expires. Offline recovery codes are one-time Identity recovery codes and still require Google authentication.

Gateway limits each approved agent to 30 reads per rolling minute and two in-flight reads, with four reads globally. Invalid/replayed assertions produce no brokerage calls. Limits are in-process and reset on gateway restart; use stop-before-start deployments and avoid frequent restarts as a rate-control strategy.

The host operations timer exports only approval/configuration records daily for seven days. It excludes OpenIddict tokens, assertion nonces, TOTP/recovery secrets, data-protection keys and brokerage tokens. The GCE persistent disk is encrypted at rest; backup exports are on that same durable encrypted disk. They protect against application-state mistakes, not disk loss; off-VM approval backups require an additional private bucket and host-only writer identity before a disk-loss recovery promise can be made.

A backup is configuration evidence, not resumable authentication. Restore into a newly provisioned authorization database, reapprove clients/agents with new identities, rotate authorization and assertion keys, and require fresh brokerage authorization. Never restore the old SQLite authentication database or gateway credentials as rollback. `authorization.db.restored` deliberately blocks startup until an operator completes offline invalidation. Read-only review of approval exports does not reactivate grants.

Replace images by stopping all old containers before starting the new pinned digests. Preserve current healthy state volumes and secret keys for normal upgrades. If recovering from a compromised or corrupted grant database, rebuild approvals and require fresh authorization. If token decryption, file permissions, locking or deletion fail, keep gateway stopped until repaired; don't fall back to an unencrypted token store. Daily E*TRADE expiration is midnight Eastern. A process restart attempts renewal of unexpired credentials; definitive rejection clears them, while transient failures retain encrypted state and require recovery before reads.

Audit rows exclude tokens, verifier codes, account data, arguments and provider errors. Retain them for 30 days. Host exports feed the Google Ops Agent; fixed JSON security events feed denial/failure/reauthorization alerts. HTTP/body debug logs must remain disabled. Monitor the HTTPS discovery uptime check and VM metrics; add project-specific availability alert policy and budgets during rollout. Alerts depend on real Ops Agent ingestion and notification delivery and need a fixture smoke test in the target project.

Certificates and image updates are operational responsibilities. Keep internal CA private key offline, rotate leaf/token/assertion credentials separately, renew public TLS before expiry and validate any updated base images. A full host or gateway compromise falls outside isolation from the MCP process.

Credential replacement requires a recent-MFA/CSRF-protected POST to `/owner/credentials/approve` with exactly `{"versions":{"consumer-key":"2","consumer-secret":"2","token-key":"2"}}`. The response is a single-use five-minute approval ID. On the VM, run `sudo python3 deploy/rotate-credentials.py APPROVAL_ID PROJECT_ID` from the reviewed checkout. The host atomically consumes approval, revokes agent grants, stops services, retrieves only approved Secret Manager versions and replaces files exclusively in the gateway secret mount. Retrieval errors leave services stopped. It removes old encrypted credentials and requires new agent approvals and fresh E*TRADE authorization. Full host administrators can bypass application approval and are outside this boundary.
